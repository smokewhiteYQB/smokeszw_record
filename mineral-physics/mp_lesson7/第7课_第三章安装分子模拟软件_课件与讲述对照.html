安装 fftw：配置命令与 PATH 概念

录音：第 1 段（前）课件 5

那么第一步呢，就是安装那个快速数据变换。这个包是啥呢？就是 fast Fourier transform，快速傅里叶变换，是一个标准的 C 程序的程序集，是那个老牌的保理人（MIT 的 M. Frigo 和 S. Johnson）开发的。很多软件几乎是通用的，都会用这个包。这个在时间域和频率域相互转换的细节我们不去管，这是数学上的。

那么要把这个包装上怎么弄呢？在你的目录里建一个目录，比方说建一个 xxx 目录，名字随便取，这里放安装包——下载完什么包就往这儿一塞；然后再建一个 zzz 目录，这个框专门安放软件，安装完了之后安装到哪去。类似于网上下载东西安装到 Program Files (x86) 里，或者你高兴也可以直接用。然后下载这个版本的包，放到目录底下解压编译。我这儿快快地讲，留一个资料放在那儿，一会儿最后演示安装一两个。

最后是配置，实际上很简单，就是 ./configure 命令。你要进行配置的话，底下放一个参数 prefix，指的是安装时想把它放到哪个路径或目录下面去——从根目录开始，一点一点放到这对里头，再起个名字，就相当于这个包安装到这个目录里面去，仅此而已。然后后面的 --enable-float，就是说我要把它编译成单精度浮点的；这个东西含有内部 double 变换，就是说给它安装成双精度，就是这个意思。

刚刚那个 --with-shared，指的是安装完之后这个包会被并行使用。因为只是串行使用没意思，给一个 CPU 弄还跑什么超算？意思是让这个包被共享，被 10 个 CPU 或 100 个 CPU 共享，就能实现并行。然后进入目录编译，执行 make install 安装。安装完后，回到目录下查看是否生成了新的文件和目录。实际上过程很简单，照做就能成功。

PATH 是什么呢？它就是一个路径。Linux 底下，它运行的东西就是特傻、也特安全：你说我要用一个文件，它说好吧，那你请告诉我这个文件在哪儿，我不会自己去找——这里头文件太多了，我不知道自己去找它在哪。那你就告诉它在地球上、在中国、在哪个地点、什么门牌号码。地址可以一个个补全，它只有一个根目录，从根目录开始，底下某个目录，再下层某个目录，一直走到末尾目录。算一下每个目录，比如 MP、202226、121，再下面的两个目录，就像刚才那个位置在这儿呢，对应这个路径所在，再下面我们一直到 openmpi 3.31.2。算一下你的 PATH，它说我终于把你这个文件找到了，OK，这就叫一条路径。

这个 PATH 里头呢，它可以放很多条。这是一条，用冒号分隔，之后再写第二条、第三条，就这样一条一条排列。给了这个之后，这就是整个 PATH，有一二三四好多条路径。机器说好，你让我用哪个命令，我就去这里头找，找得到就执行，找不到就报错，就是这个意思。现在要追加一条是什么意思呢？原来是一堆路径，你让 PATH 等于这样一条新的 PATH 在它的前头，那就是把一个路径写到这些的前头；又弄一条，加冒号，然后看电压，这就叫电压。

安装 OpenMPI：环境变量与 which 检查

录音：第 1 段（前）课件 6

下面再安装 OpenMPI，因为它稳定好用，现在大家都喜欢用。OpenMPI 即开放源码的消息传递接口（Message Passing Interface），负责 CPU 间的通讯——比如发送和接收任务，都通过 MPI 进行。操作类似：去官网下载，放入目录，cd 进入并解压，接着 cd 到目录中进行配置，指定安装路径，路径设在用户目录下的 bin 中。操作不难，只是重复步骤，但不同于普通软件。

这个包安装后需配置环境变量使其生效，目的是让系统能找到 OpenMPI 中的 mpicc 并行编译器。只有安装完成后，mpicc 才会出现。如何让系统找到 mpicc 的路径？打开家目录下的 .bashrc 文件，在末尾追加一行 PATH 和一个环境变量库路径。注意不要多打等号，修改后执行 source 命令使环境变量生效。接着用 which mpicc 检查是否设置成功——若找不到则说明未生效。资料中的目录名如 xxx、zzz 可自定义，但需记住 FFTW 和 OpenMPI 的位置。

安装 CMake：跨平台构建工具

录音：第 1 段（前）课件 7

先安装 OpenMPI 包，再安装 CMake 包。以前不装 CMake 会导致后续配置库路径很麻烦：包含文件在哪儿？这个文件在哪儿？那个文件在哪儿？一来多了好多这样细碎的事。有了 CMake 之后，CMake 是一个跨平台的构建工具，它就会自动检查系统环境是什么、依赖的库是什么、设置的编译选项是什么，去管理代码的整个结构。最后它的目的就是生成一个脚本叫 Makefile，里头含有各种信息，告诉机器在编译的时候要用 GCC 或者 MPICC 那种编译器进行编译。

它既然是自动化的，那好了，就是说平常同学们要指定这个、指定那个那些啰嗦的事，它都能自动完成。那这样一来，把它装上就好了。把这个 CMake 包解压缩进到里头去，前面那几个用的是 configure 命令，它这个特征叫做 prefix，这个命令同样指定了一个路径前缀名，就是把它安装到某个软件的目录底下去，这种 software 就相当于就是一个目录。放到这儿去，然后加一个编译的参数，把什么都关掉，就这意思。弄完之后，编辑进去，然后追加一个 PATH，把那个 PATH 追加一下——这里已经提到过两次了，这个追加 PATH。

找到后可以继续安装 CMake。解压后 CD 进去，这里有个 build 目录，按说明书建议进入其中。设置环境变量，指定 FFTW 的路径，将 GMS 2025 目录加入路径，这是 gmax 启动用的。启用 MPI 支持，检查 MPICC 是否安装。使用 make -j4，利用 4 个 CPU 并行编译提速——原本需 10 分钟，现在约 3 分钟完成。根据情况调整，稍后讲解平台注意事项。

安装完成后，将 gmax 路径追加到 PATH 并生效，检查确认无误即可。这解决了前几个依赖包问题。需用 MPI 编译成并行版本，CMake 已生成 Makefile，无需手动修改，直接使用即可。如果你去年没用 CMake，就要写三四条指令，需指定包含文件、库及选项，写不清楚编译会报错。

安装 Gromacs：CMake 配置与并行编译

安装注意事项：版本选择与纠错心态

录音：第 1 段（后）课件 10

安装这个 mpi 的时候呢，有时候需要检查自己的各种版本。这个指的是什么呢？就是版本有好多种，你怎么知道安装的这个版本就适合你呢？那么到高阶阶段的时候，你比方说我要安装那个 3.11 版的，人家说还有个 4.18 版还更好，还有个 5.2 几版的也一样好，是不是合适呢？你可以安装 3.11 版的跟你这个 Gromacs 结合一下，然后你跑一个数据作为比对流量；你再安装一个 4.18 版的，安装完成后你就可以跑 Gromacs，跟 3.18 版的 mpi 效果一样。你也跑一个数据比对，觉得哪个快就留哪个。到了高阶阶段就这样对包——我用这个包那个包，Mpi 也有多个版本都可以，中间只要把它换了就行。

那安装 Gromacs 的也有不同的版本和型号。比方说 Gromacs 安装完后需要单独设置：单精度的跑得快，另一个 Gromacs 要安装成双精度的，算得准。这东西就是这样，不太可能既算得准又算得快——那样的话，单精度早被淘汰了。所以大多数跑得快的都是单精度跑就可以了。后面我们会给你们讲案例，有的东西必须要用双精度的去跑，才有可能做出一项科研。那种情况下，你要说不会安装、不知道这一点，你这辈子都在用单精度的跑，那你还怎么创新？就把很多创新的选项都给丧失了。所以这就是我们尽量让你们从更低一层的台阶往上走，就是做一点底层的东西。

再一个就是不要怕出错，也不要指望安装过程是一帆风顺的。什么错都没有？行，恭喜你，真的太好了，你刚入门就把软件都安装好了，那很好。但是确实是在解决问题的时候、在遇见挫折和失败的过程中，你才能够学到很多，提高得快，理解得多，印象很深。我们遇见的困难太多了：几十年前有网络就不错了，有时为了查资料整宿都过不去，软件老编译不成，很麻烦。出过错，才能更快掌握要领。
